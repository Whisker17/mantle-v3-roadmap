## 2. 场景一：Tape Meme Launchpad 对 Agent 账户的硬性需求

### 2.1 业务特征回顾
- **以代币化股票（xStocks，如 NVDAx, TSLAx）为唯一计价 Quote 资产**；
- **Spend-Gate 门禁**：打新额度受用户持有资产（mETH、xStocks）与 Bybit VIP 等级约束；
- **极速相变式 Bonding Curve**：代币达到 $12,000 阈值瞬间在 Hook 内原地相变，零迁移、零延迟。

### 2.2 Agent 在 Tape 中的典型痛点与账户层需求

```
 传统 EOA 交互链路 (存在致命痛点):
   [人类钱包] ──(私钥全权暴露)──► [云端 Python 狙击 Bot] ──(等待 Approve 上链)──► [Mempool 排队]
                                                                                │ (被夹子抢跑)
                                                                                ▼
                                                                        [购买失败但浪费 Gas]

 新一代 Agent 账户交互目标:
   [人类主账户] ──(签发 100 NVDAx 受限 Session Key)──► [Tape 狙击 Agent]
                                                              │
                                    (原子化 Approve + Buy，走专属并发通道)
                                                              ▼
                                              [Sequencer 直达 / 毫秒级成交]
```

#### 需求 1：代币化股票的原子授权与买入（Zero-Approval Multi-Call）
- **痛点**：打新以 NVDAx/TSLAx 计价，传统模式需先发送 `NVDAx.approve(TapePool)`，确认后再发送 `TapePool.buy(NVDAx, amount)`。两笔交易在 2 秒出块的 L2 上至少造成 **4 秒延迟**，狙击早已宣告失败。
- **账户层诉求**：**必须支持原生原子批处理（Batching）**，在一笔原子交易中同时完成额度划转与合约交互，杜绝被夹与分步延迟。

#### 需求 2：Spend-Gate 额度与资产隔离（Strict Scoped Session Policy）
- **痛点**：用户账户中通常沉淀了大量优质底仓资产（如价值 $50,000 的 mETH 和 NVDAx）。如果给打新 Agent 提供主私钥，一旦外部开源抢跑脚本存在后门，用户整仓资产将付之一炬。
- **账户层诉求**：主账户能够签发**限权 Session Key**：
  1. 仅限调用 `TapeLaunchpad` 合约；
  2. 仅限支出不超过 `500 NVDAx`；
  3. 仅在美股开盘前后的 `30 分钟` 窗口期内有效；
  4. 即使 Agent 私钥泄露，黑客也无法触碰用户账户中的 mETH、USDT 或其他 xStocks。

#### 需求 3：多 Token 并行打新与线头阻塞消除（Independent Concurrency Channels）
- **痛点**：当财报季来临，可能同时有基于 NVDA、AMD、MSFT 的多个 Meme 标的发起。Agent 同时向不同池子发送买单。若一个池子因达到单块 Spend-Gate 上限发生 Pending，绝不能拖死另外两个池子的抢买。
- **账户层诉求**：必须具备**多维并发 Nonce（2D Nonce）**，不同标的的打新交易走不同的流水线，完全隔离。

## 3. 场景二：股票 Perps 衍生品对 Agent 账户的硬性需求

### 3.1 业务特征回顾
- **代币化美股 24/7 全天候杠杆合约**（Oracle-based 起步，Ostium/GMX 模式）；
- **休市定价机制**：周末与夜间美股休市，Index Price 冻结，Mark Price 链上多空博弈，具有独特的资金费率收敛曲线；
- **Mantle 专属原生链支持**：Dedicated Liquidation Lane（清算优先通道）、Revert Protection（模拟免拒）。

### 3.2 Agent 在 Perps 中的典型痛点与账户层需求

```
                      ┌─────────────────────────────────────────────────────────────┐
                      │              股票 Perps 自动化风控与套利时钟                │
                      └──────────────────────────────┬──────────────────────────────┘
                                                     │
                             ┌───────────────────────┴───────────────────────┐
                             ▼                                               ▼
               【基差套利 Agent (高频双腿)】                    【仓位自保 Agent (高危救火)】
               • 监控 Perp 资金费率与现货溢价                  • 监控 Mark Price 与爆仓线距离
               • Leg 1: Perp 市场做空                          • 触发阈值: 距清算仅剩 1.5%
               • Leg 2: Fluxion RFQ 现货买入                   • 动作: 毫秒级从金库划转 Margin
                             │                                               │
                             ▼                                               ▼
               【账户层要求: 原子批处理】                      【账户层要求: 绝对无阻塞通道】
               • 确保双腿要么全成，要么全退                    • 独立 Nonce 通道，免受做市挂单阻塞
               • 拒绝单腿裸头寸暴露风险                        • 专有保证金划转权限，禁转外部地址
```

#### 需求 1：跨协议原子双腿对冲（Cross-Protocol Atomic Execution）
- **痛点**：基差套利的利润极其微薄（年化 15%–35%，单笔利润不足 0.1%）。如果开空 Perp 成功，但在前往 Fluxion RFQ 买入现货时交易失败或因 Nonce 阻塞滞后，Agent 就会被迫暴露在单向巨大敞口之下。
- **账户层诉求**：账户能够原生编排：
  `[Perp.openShortPosition] -> [FluxionRFQ.fillQuote] -> [VerifyBasisSpread]`
  三步在单笔交易内原子执行，若基差偏离预期则全单回滚，不造成资金亏损。

#### 需求 2：仓位自保的「绝对无阻塞通道」（Zero-HoLB Emergency Lane）
- **痛点**：高频做市 Agent 通常每秒发送数十笔微调报价的订单。在极端行情剧烈波动时，现有持仓由于价格暴跌瞬间逼近清算线。如果自保补仓交易排在高频撤挂单后面，由于 Nonce 串行，**补仓资金在 Mempool 排队时，仓位已经在链上被 Liquidator 强制爆仓！**
- **账户层诉求**：自保 Guardian Agent 必须拥有**专用的独立 Nonce 通道（Priority Execution Lane）**，该通道与日常交易策略完全解耦，确保紧急追加保证金交易零排队即时落块。

#### 需求 3：动态熔断断路器（On-Chain Stop-Loss Circuit Breaker）
- **痛点**：在休市定价与周末交易中，市场流动性较薄。若 Agent 的 AI 模型因极端外部新闻出现判断幻觉，持续以市价单大幅拉抬或砸盘，可能在数分钟内将保证金耗尽。
- **账户层诉求**：账户层内置风控 Hook（策略断路器）：
  1. 设定「单日最大允许已实现亏损（Max Realized Loss）」；
  2. 一旦仓位累计亏损触及阈值，合约底层自动剥夺 Agent 的 Session Key 执行权限，并将现有头寸转入市价平仓状态，锁定本金安全。

## 4. 两大业务场景对账户层特性的硬性需求对比

下表直观呈现了 Tape Launchpad 与 股票 Perps 对 Agent 账户模型的差异化指标要求：

| 评估维度 / 指标 | Tape Meme Launchpad (打新/抢跑) | 股票 Perps (衍生品做市/套利/风控) | 对底层账户模型的刚性要求 |
|---|---|---|---|
| **核心操作延迟** | < 200ms（毫秒级争夺头矿） | < 500ms（高频对冲与爆仓拯救） | **拒绝 Bundler 延迟，必须 Sequencer 直达** |
| **交易并发性** | 多代币并行打新（并发度 10–50） | 做市挂单与补仓并行（并发度 50–200） | **必须支持多维 2D Nonce，消除线头阻塞** |
| **单笔 Gas 承受阈值** | 极度敏感（打新利润往往小额） | 中度敏感（高频调整累积开销大） | **基础验证 Gas < 35,000，拒绝 4337 高额磨损** |
| **原子批处理能力** | 必须支持 Approve + Buy 原子化 | 必须支持 Perp + Spot 跨协议双腿原子化 | **原生支持 Multi-call Batch Execution** |
| **权限隔离范围** | 限定单一代币池、固定额度、短时效 | 限定 Margin 资产、限定 DEX 合约、长期守护 | **细粒度 Session Key 策略引擎** |
| **链上风控断路器** | 滑点限制、防重入、防假币授权 | 累计最大回撤熔断、杠杆上限强制钳位 | **账户层 / 预编译层 Hook 策略拦截** |
| **Gas 支付形态** | 官方 Paymaster 全额补贴或 xStocks 扣费 | 支持 USDT / mStocks / 保证金直接付 Gas | **原生协议级 Paymaster 代付能力** |

**结论**：无论是 Tape Launchpad 还是 股票 Perps，对账户模型的共同诉求都清晰地收敛到了：**「原生极速响应、多维并发独立通道、细粒度 Session 限权、原子批处理与协议级代付」**。这为我们下一章设计 Mantle v3 专属的 Agent Account 整体架构提供了清晰明确的规格指引。
