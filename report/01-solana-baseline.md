## 1.0 先建立正确的心智模型：meme 交易是一个四层栈

大多数人把 "pump.fun" 和 "GMGN" 混为一谈，这是理解整个赛道的第一个障碍。它们处在完全不同的层：

```
┌───────────────────────────────────────────────────────────┐
│ 第 4 层  发现与执行层  GMGN / Photon / BullX / Axiom /     │  ← 用户实际在这里操作
│                        Trojan / Bloom（终端与 bot）        │
├───────────────────────────────────────────────────────────┤
│ 第 3 层  聚合与路由    Jupiter / 各终端自建路由             │
├───────────────────────────────────────────────────────────┤
│ 第 2 层  发行与流动性  pump.fun / LetsBonk / Believe（曲线）│  ← "launchpad" 指这一层
│                        PumpSwap / Raydium / Meteora（AMM）  │
├───────────────────────────────────────────────────────────┤
│ 第 1 层  链             Solana（LFM / 并行执行 / 400ms）    │
└───────────────────────────────────────────────────────────┘
```

**关键洞察：这四层的价值捕获能力完全不同，而且是第 4 层最强。**

在 Robinhood Chain 上可以看到最直白的证据：单个交易终端 **GMGN 一家吃掉全链约 40% 的 DEX 交易量（24h $641.7M）**，而 launchpad 龙头 Pons V2 只有 $161.4M。

> ⚠️ **这条对 Mantle 极其重要**：Mantle 目前的状态是「有第 1 层、有第 2 层的雏形、有第 3 层、**第 4 层完全为零**」。
> 详见第四部分 4.3 —— GMGN / Photon / BullX / Axiom / Trojan / Banana Gun / Maestro **全部不支持 Mantle**。

### GMGN 是什么

GMGN（"Good Morning, Good Night"）是一站式 meme 交易终端，把**数据看板 + 聪明钱追踪 + 狙击 bot + 抗夹 RPC** 打包成一个产品。支持 Solana / Ethereum / Base / BSC / Tron / **Monad / HyperEVM / MegaETH / X Layer / Robinhood Chain** —— 注意这个清单里**没有 Mantle**，却有比 Mantle 更新更小的链。

它的三个核心能力：
1. **快** —— 自建节点 + gRPC 流式订阅，1 秒级响应
2. **准** —— 把持仓结构、老鼠仓、庄家占比等原始链上数据可视化
3. **全** —— 发现（新池监控）→ 分析（安全检测：是否烧池、权限是否丢弃）→ 执行（狙击/跟单）→ 风控（防 MEV）全链路

**"Trenches（战壕）"** 是它的多栏行情面板 —— 一个高密度的"作战指挥室"，同时显示新池监控、pump.fun 打满信号、热门排行。

> **GMGN 的存在本身就是一条链"meme 就绪"的认证标志。** 一条链如果 GMGN 不支持，就等于对整个 meme 交易者群体不可见。

### 1.1.1 链上真实常数（本报告直接解码）

> ### ⚠️ 辟谣一：`1,073,000,191` 是错的
> 这个数字在中英文社区、多个 SDK README、乃至 AI 摘要中被反复引用。
> **链上字节是 `1073000000000000`，对应 1,073,000,000 整。**
> 二者代入曲线后毕业募资额差异仅约 0.00001 SOL，所以从未被发现 —— 但写代码时必须用真值。

### 1.1.2 供应量切分

```
总供应              1,000,000,000  (100.00%)
├─ 曲线可售           793,100,000  ( 79.31%)   ← initialRealTokenReserves
└─ 毕业时进 LP        206,900,000  ( 20.69%)
```

`206,900,000` 在 2026-09-06 的三笔真实迁移交易中被逐笔验证为**恒定值**。

### 1.1.3 恒定乘积不变量

```
k = vSOL₀ × vTOK₀ = 30 × 1.073×10⁹ = 3.219×10¹⁰  (SOL·token)
```

**"virtual reserves" 是纯记账数字，池子里并不真的有 30 SOL。**
它的作用是给曲线一个**非零起始价**并压平初期斜率 —— 如果从真实储备 0 开始，第一枚代币价格为 0，第一个买家会以近乎免费的价格吃掉全部供应。

### 1.1.4 买入 / 卖出公式（程序内部 u128 整数运算）

**买入**（给定投入 lamports `Δs`，已扣手续费）：
```
vSOL' = vSOL + Δs
vTOK' = ⌊ (vSOL × vTOK) / vSOL' ⌋ + 1      ← +1 向上取整，防舍入套利
Δt    = vTOK − vTOK'
Δt    = min(Δt, realTokenReserves)          ← 曲线售罄即触发毕业
```

**反向**（"我要买 N 枚，最多付 M lamports"）：
```
Δs = ⌊ (vSOL × Δt) / (vTOK − Δt) ⌋ + 1
Δs_total = Δs × (1 + fee)                   ← 费用加在成本之上，非从中扣除
```

**卖出**：
```
Δs = ⌊ (Δt × vSOL) / (vTOK + Δt) ⌋
Δs_net = Δs × (1 − fee)                     ← 费用从返还额中扣除
vSOL −= Δs ,  vTOK += Δt
```

**现货价与市值**：
```
P  = vSOL / vTOK
MC = P × 1,000,000,000
```
- **开盘价** = 30 / 1.073e9 = `2.795899e-8` SOL/token → **开盘市值 27.959 SOL**
- **毕业价** = 115.005359 / 279,900,000 = `4.108802e-7` → **毕业市值 410.880 SOL**
- **全程涨幅 = 14.6958×**（**结构性常数，与 SOL 价格无关**）

### 1.1.5 「85 SOL 毕业」的严格推导

曲线售罄定义为 `realTokenReserves = 0`：
```
vTOK_end = 1,073,000,000 − 793,100,000 = 279,900,000
vSOL_end = k / vTOK_end = 32,190,000,000 / 279,900,000 = 115.005359 SOL
真实募得 = 115.005359 − 30 = 85.005359 SOL
```

> ### ⭐ 关键结构性洞察
> **`30 SOL`、`1.073B`、`793.1M` 一旦给定，`85.005359 SOL` 的毕业募资额与 `410.88 SOL` 的毕业市值就被完全确定，无自由度。**
> 这三个"神奇数字"不是三个独立参数，是同一个方程的推论。
> **→ 设计新 launchpad 时只需选定其中三个自由度，其余全部被锁死。这是曲线设计的第一课。**

### 1.1.6 曲线阶梯表 —— 理解 sniper 军备竞赛的经济根源

| 累计入池 SOL | 已售代币 | 占总供应 | 现价 | 隐含市值 | 距开盘 |
|---|---|---|---|---|---|
| 0.000 | 0 | 0.00% | 2.7959e-8 | 27.96 | 1.00x |
| 1.000 | 34,612,903 | 3.46% | 2.9854e-8 | 29.85 | 1.07x |
| 10.000 | 268,250,000 | 26.82% | 4.9705e-8 | 49.70 | 1.78x |

| 60.000 | 715,333,333 | 71.53% | 2.5163e-7 | 251.63 | 9.00x |
| **85.005** | **793,100,000** | **79.31%** | **4.1088e-7** | **410.88** | **14.70x** |

> ### ⭐⭐ 曲线形状的经济含义（全报告最重要的机制洞察之一）
> **前 30 SOL（募资额的 35%）就卖掉了 53.65% 的供应；最后 25 SOL 只卖掉 7.8%。**
> 这是一条**极度前置倾斜（front-loaded）**的曲线 —— 早期买家拿到绝大部分筹码。
>
> **这正是 sniper bot 军备竞赛的经济根源：第一个区块的价值远超后面所有区块之和。**
>
> **推论**：任何 launchpad 若不主动"抹平前几秒的超额收益"（衰减税 / 批量拍卖 / 固定价格窗口），
> 机器人军备竞赛就是曲线数学的必然结果，不是治理问题。

### 1.1.8 「$69k 毕业」是一个汇率幻觉

毕业市值恒为 **410.8802 SOL**。美元值随汇率线性漂移：

| SOL 价格 | 毕业市值 (USD) |
|---|---|
| $100 | $41,088 |
| **$167.93** | **$69,000** ← 这才是 $69k 的来历 |
| $200 | $82,176 |
| $300 | $123,264 |

**为什么阈值以代币数量而非美元定义**：`complete` 标志由 `realTokenReserves == 0` 触发，是纯代币数量条件。曲线数学只涉及 SOL↔Token 的虚拟储备关系，**程序内完全不知道 SOL 的美元价格（没有预言机）**。

| | 好处 | 代价 |
|---|---|---|
| 无预言机的纯数量阈值 | 无操纵面、完全确定性、可被 bot 精确预测 | **牛市中毕业门槛（美元）自动抬高，熊市自动降低 —— 反周期地放大牛市毕业难度** |

> four.meme 恰恰选了相反的路线：**把所有计价资产的毕业阈值统一校准到约 1.2–1.8 万美元等值**，
> 并在 BNB 涨价时把 24 BNB 降到 18 BNB 以维持美元门槛恒定（详见第二部分 2.1.3）。
> **→ Mantle 的设计必须在这两条路线之间做出明确选择。我的建议见第六部分 6.3.3。**

### 1.2.2 dev buy（创建者首购）

- `CreateV2` 与 `buy` 可放在**同一笔交易**内。真实交易解码显示参数为"买 3,564,784.05 枚，最多付 0.105 SOL"，反算成交价与标准开盘价 `2.795899e-8` 一致。
- **无任何官方锁仓 / vesting。创建者可随时清仓。**
- 平台层面唯一约束是**社会性的**：GMGN / Photon / Axiom 等终端会把 "dev sold" 标为红色风险信号，形成事实上的声誉惩罚。

> **经济后果**：dev 在曲线最低点建仓，成本比后续买家低一个数量级。结合 1.1.6 的前置倾斜曲线，**这是 "dev rug" 能持续获利的结构性原因。**
> → 任何新 launchpad 若不处理 dev 建仓成本问题（vesting / 限购 / 强制锁），就是在制度化 rug。

### 1.2.3 曲线交易阶段

- **主程序**：`6EF8rrecthR5Dkzon8Nwu78hRvfCKubJ14M5uBEwF6P`
- **PDA**：Global `["global"]`；Bonding Curve `["bonding-curve", mint]`
- **BondingCurve 账户布局（151 字节）**：
  ```
  disc(8) | virtualTokenReserves u64 | virtualSolReserves u64
         | realTokenReserves u64 | realSolReserves u64
         | tokenTotalSupply u64 | complete bool(1) | creator Pubkey(32) | ...
  ```
- **`complete` 标志位**：售罄后置 1，此后 `buy`/`sell` 被拒绝，交易只能转到 PumpSwap。
- **滑点保护**：`buy` 用 `max_sol_cost`，`sell` 用 `min_sol_output`。
- **优先费**：官方建议 0.003–0.01 SOL；防夹/抢跑模式 0.01–0.03 SOL。

## 1.3 费用体系演进：1% → 1.25% 不是涨价，是重新分配

### 1.3.1 曲线阶段的真实拆分

```

├── 95 bps → 协议     （从原来的 100 bps 降下来）
```

> ### ⭐ 关键解读
> **协议自己从 100 bps 降到 95 bps，新增的 30 bps 全部转给创作者 —— 用买家的钱补贴供给侧。**

## 1.6 MEV：Solana 的 sandwich 与防夹机制

### 1.6.1 无全局 mempool 不等于无 MEV

Solana 没有以太坊那样的公开全局 mempool。交易通过 **Gulf Stream** 直接转发给当前及即将上任的 leader，配合 **QUIC** 经 TPU 进入验证者，验证者据此做 **swQoS（Stake-Weighted QoS）** 分级 —— 高质押权重连接获得优先转发配额。

**但 MEV 依然存在，根源是 leader schedule 的可预测性**：leader schedule 在每个 epoch 开始前就确定并公开。任何时刻"谁将打包接下来 4 个连续 slot"是已知信息，搜索者可针对具体 leader 建专线直连抢先嗅探交易流，或与该 leader 合谋。

> **全局公开队列消失了，但局部可预测性取代了它。**

### 1.6.2 sandwich 的实际规模

一个典型攻击（Helius 案例，2024-12-16，Komeko 代币）：三笔交易打包为 Jito atomic bundle，tip 0.000148 SOL，净赚 0.01678 SOL（约 $3.35）。

**量化损失**：
- Helius（`vpe` 程序，30 天窗口）：**155 万笔交易，获利 65,880 SOL（$13.43M）**，年化约 801,540 SOL，占全网 sandwich 约 **50%**，支付 Jito tip 22,760 SOL（$4.63M）
- Sandwiched.me（16 个月，8.5B 笔交易 / $1T DEX 量）：全网 sandwich bot 累计提取 **$370M–$500M**；单月峰值 2024-11 近 60 万 SOL；**全网验证者 sandwich 率中位数 2.4%，部分验证者 20%–60%**

**恶性循环**：DeezNode 运营的验证者质押从 2024-11-13 的 30.79 万 SOL 暴涨至 12-09 的 80.25 万 SOL（19.89% 来自 Marinade mSOL），形成 **质押 → 更多 leader slot → 更多 MEV → 更高 APY → 吸引更多质押** 的正反馈。

### 1.6.3 Jito 2024-03 关闭 mempool

- **原因**：200ms 交易预览窗口被系统性用于 sandwich，Jito 形容为"猫鼠游戏"无法根本赢，**主动牺牲 tip 收入关闭**。
- **结果**：sandwich 数量断崖式下跌，**一个月内迅速恢复**。
- **转移去向**：① 私有订单流；② 验证者自营 sandwich 机器人（单个程序贡献全网近一半攻击量）；③ **"宽夹"（wide sandwich）兴起** —— 为对抗 `jitodontfront` 机制，前后交易分开发送（间隔 50–300ms），**宽夹占比暴增近 30 倍**。

### 1.6.4 防夹 RPC 的原理与局限

**原理**：
1. **Jito bundle 原子性** —— 多笔交易打包为原子单元，全部按序执行或全部不执行。`jitodontfront` 约定让用户附加哨兵账户，验证者据此拒绝将该交易插入 sandwich bundle 中间。
2. **私有交易通道** —— `sendTransaction` 直接发给私有 relay，该 relay 只与可信验证者或 Jito Block Engine 建专线，绕开公开可监听的 QUIC/TPU 入口。
3. **黑名单式路由**（Helius MEV Protect）—— 监控 sandwich 机器人及获利落地验证者并标记，开启 `mev-protect=true` 后避开这些验证者转发。
4. GMGN / BullX / Photon 采取"默认路由至 Jito Block Engine + 可选 MEV Protect Mode"策略。

**六条局限**：
1. 黑名单**滞后性**，新验证者可在被拉黑前完成多轮攻击
2. **宽夹无法被 bundle 原子性防御** —— 分开发送即绕过 `jitodontfront`，这是宽夹暴增 30 倍的直接原因
3. 私有 relay 本身可能被攻陷或勾结，制造更隐蔽的观测点
4. 黑白名单治理与去中心化的悖论
5. **验证者自己是攻击者时，用户端无法验证其是否老实排序**
6. 保护与速度权衡：仅走单一通道，拥堵时可能降低成交速度

> ### ⭐ 结论
> **"防夹"是风险缓释而非密码学保证。只要 leader 对本 slot 交易顺序有最终裁量权，sandwich 的经济激励就不会归零。**
>
> **→ 对 Mantle 的启示（一个被严重低估的优势）**：Mantle 是**单一中心化 sequencer 的 OP Stack 链，没有公开 P2P 交易池**。
> 这意味着 **Mantle 天然不存在公开 mempool 可供嗅探 —— 结构上抗三明治**。
> 这是 Mantle 相对 BSC / Ethereum 真实且稀缺的优势，**但从未被宣传过**。详见第五部分 5.7。

### 1.6.5 BAM（Block Assembly Marketplace，2025-07）

Solana 版 PBS，三组件：
- **BAM Node**（TEE Scheduler，如 AMD SEV-SNP，执行前保密排序，事后产出密码学证明）
- **BAM Validator**（运行更新版 Jito-Solana / FireBAM 客户端）
- **Plugin**（自定义排序逻辑接口）

理论上压制验证者随意插单，但 **TEE 存在侧信道攻击先例，且 BAM 仍由 Jito 中心化运营**。

## 1.7 为什么 Solana 的 infra 适合 meme：机制级论证

这一节是第五部分（infra 需求框架）的理论基础。

### 1.7.1 Local Fee Market（LFM）

```
Prioritization Fee = Compute Unit Limit × Compute Unit Price (micro-lamports/CU)
```

**关键**：竞价按每笔交易**实际写入的账户集合**局部生效（Agave 1.18 中央调度器构建 "prio-graph" 依赖图），**不同账户集合间互不影响价格**。可用 `getRecentPrioritizationFees` 按具体账户查询行情价。

**三个直接后果**：
1. 一个爆款 meme 的抢购，**不会**把全链 gas 拍高
2. 因为费用 = CU limit × CU price，**虚报 CU limit 会自我惩罚** → 天然抑制垃圾交易膨胀
3. 开发者被激励去优化交易形状（减少 writable accounts、减少签名）

### 1.7.2 单账户写配额硬顶 —— 被严重低估的一条

**SIMD-0286 于 2026-07-29 激活**：区块上限 60M CU → **100M CU**（+66%），**未改动 400ms 出块**（另有报道称 2026 年 slot 已降至 350ms，需二次核实）。

升级前数据：约 **11.2% 的区块已触顶**（≥56M CU）。

> ### ⭐⭐⭐ 最关键的一条
> **升级没有提高单账户写上限 —— 任一 writable account 在单区块内仍最多消耗 12M CU。**
>
> 含义：即使一个 meme 合约有无限需求，**它最多只能占据区块的 12%**。
> 剩余 88% 的空间对其他应用是**受保护的**。
>
> **这就是"热点争用隔离"的工程实质 —— 不是让热点更快，而是给热点划一个笼子。**

Block accounts data size delta 上限仍为 100MB。
历史路径：SIMD-0256（2025-07）50M→60M；SIMD-0286（2026-07）60M→100M。

> **对"弹性可调节区块空间"这个问题的答案**：
> Solana 的落地形态**不是"按需扩张"**，而是三件套：
> ① **治理驱动的总量分级抬升**（SIMD）
> ② **单账户写配额硬顶（12M CU）**
> ③ **按写锁定价的 LFM**
> **三者缺一不可。** 只抬总量而不设单账户顶，热点合约会重新吃满全区块；只设顶而无 LFM，热点合约的用户会被无差别挤出。

### 1.7.3 其他适配性

| 特性 | 对 meme 的意义 |
|---|---|
| **并行执行 + 写锁模型** | 不同代币的交易天然并行，互不阻塞 |
| **400ms slot** | 反馈环足够短，PvP 博弈可玩 |
| **单一 SOL 资产** | 无双代币摩擦（对比 Mantle 需要 ETH 跨桥再换 MNT） |
| **账户模型 + PDA** | 每个代币的曲线是独立账户，天然隔离 |
| **成熟的机器化交易栈** | swQoS / staked connection / Jito bundle / Yellowstone Geyser gRPC 全部就位 |
| **失败交易成本极低** | 狙击战中高失败率是常态，低成本才养得起 bot 生态 |

### 1.7.4 一笔抢开盘交易的完整技术路径

```
1. Yellowstone Geyser gRPC 流式订阅 → 毫秒级捕获 CreateV2 事件
2. 本地模拟计算最优买入量与滑点
3. 构造交易：ComputeBudget(setComputeUnitLimit + setComputeUnitPrice) + buy 指令
4. 可选：打包成 Jito bundle 并附 tip
5. 经 staked connection / 私有 relay 发送给当前 leader
6. 400ms 内确认
```

**每一环都有商业化的基础设施供应商。这套栈在 Mantle 上一个都没有。**

## 1.8 本部分对 Mantle 的可迁移结论

1. **bonding curve 的三个自由度一旦选定，其余全部锁死** —— 设计时先想清楚要锁哪三个。
2. **曲线是极度前置倾斜的，这是 sniper 军备竞赛的数学根源** —— 必须主动抹平前几秒的超额收益，不能靠治理。
3. **毕业不应带来用户可感知的成本跳变**（Ascend tier 0 上界 420 SOL 的设计）。
4. **launchpad 与毕业目的地 DEX 的所有权关系，决定 7% 量级的利润归属**（6 SOL 过路费的教训）。
5. **LP 销毁是最强信任信号，但会孤儿化费用收益** —— Uniswap v4 的 "永久锁 + Fee Key" 是更优解（见第二部分 2.2）。
6. **日发币量是虚荣指标**，毕业数 × 毕业后存活率才是真指标。
7. **热点争用隔离的工程实质是"给热点划笼子"，不是"给热点扩容"** —— 这是第五部分的核心论点。
8. **Mantle 的无公开 mempool 是一个未被宣传的真实优势**，但它同时也消灭了做市（见第四部分 4.4）。
9. **执行层（第 4 层）的价值捕获能力最强，而 Mantle 完全为零** —— 这是第四部分的核心诊断。
