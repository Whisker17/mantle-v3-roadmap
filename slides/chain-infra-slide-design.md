# Mantle v3 分享：章节与页面规划

本稿依据 [chain-infra.mdx](references/chain-infra.mdx) 组织内容，并纳入用户最新的“资产发现 + 资产交易”导图。交付物是每页的内容说明与精简文案；全稿使用 [Mantle 深色制作规范](prompts/Mantle-dark-capital-markets.md)，主题页 P00 另给排版说明。[ASCII 生态总览及产品关系评审](narrative-product-fit.md) 单独保留，各 slide 不恢复逐页草图。

## 对原文主线的理解

原文从三项正在推进的工作出发：Glamsterdam 适配保障链继续运行，mStocks 增加资产供给，PropAMM 与聚合器改善成交。已有资产与资金，还需要能让用户持续参与的产品，因此引出 Agentic Launchpad 和 Perps。

两个产品分别提出自动化授权、交易反馈、排序、资源和组合交易的要求。先判断合约与服务能否满足这些要求，再讨论 AA 和执行架构。Fully Onchain Perps 是长期目标，通用 EVM、专用模块和独立 L3 是不同实现路线，原文没有预先选定其中一条。

这决定了各章的分工：Section 0 讲为什么做，Section 1 讲用户怎样参与、产品如何运转，Section 2 讲哪些能力可共用和应该在哪实现，Section 3 讲账户方案，Section 4 讲执行路线。收尾把原文 0.1 的讨论目标落实为待确定的任务。

本轮将“资产发现 + 资产交易”作为两条讲述主线：发行与外部引入提供资产基础，终端与社区帮助用户发现资产，现货与 Perps 支持交易，Lending 和 Vault 按实际用途支持资金使用。AA 与链能力横向服务所有流程。两条主线不预设部署架构，也不将扩展产品自动纳入首批开发。

## 每页的统一结构

每个章节先有一张分隔页：章名、一句话主旨、阅读路径。使用 [统一深色分隔版式](prompts/Mantle-dark-capital-markets.md)，P00 总封面不能替代 Section 0 的入口。分隔页仍填写下列四项，便于直接交给制作 agent。

每章最后另有总结页 C0–C5/CA：用结论标题和少量支撑判断回答本章得出了什么，标明其正文依据，并保留影响下一步的条件。分隔页提出问题，总结页给出判断；两者不能复制同一段主旨或导航。

1. **本页要讲什么**：用一小段话说明唯一的主要观点。
2. **对应原文**：给出准确的小节编号和标题。两个 0.4 用标题区分，不能只写编号。
3. **需要的图文及原因**：明确需要哪种内容，例如资金流图、流程对照、真实截图或简表；列出应包含的对象和关系，并解释它帮助听众理解什么。纯文字足够时直接说明，无须每页配图。
4. **上屏文案**：给出最终标题、正文、图中文字与必要图注。图中文字也算上屏文案，不能留给制作 agent 随意编写。

复杂页可另有简短的“讲述补充（不上屏）”，用于解释不适合塞进幻灯片的技术细节。

文案目标：一般页标题加正文与图注尽量控制在 120–180 个中文字符附近，流程/对照页可适当放宽到 220 个字符；宁可删重复内容，不把完整段落拆成很多短句。标准编号、金额、英文术语使字符数只适合作为密度提示，仍以人读起来是否清楚为最终判断。
