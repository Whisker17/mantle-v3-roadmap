# Mantle v3 核心叙事与产品关系评审

## 1. 评审结论

你的导图已经抓住了资产供给、成交质量、Agent 参与和交易场景四个重点。需要调整的是层级：图里把资产类别、产品、参与者和基础设施放在了相近的位置，还缺少用户从发现资产到成交、持有、对冲和退出的连接。

建议保留 **“资产发现 + 资产交易”** 作为对外讲述的两条主线，用一句话说明：

> **让用户和 Agent 找到值得参与的资产，并在 Mantle 完成交易、管理风险、持续使用资金。**

发行和引入资产是这两条主线的供给基础；终端与分发负责让用户找到资产；报价和交易产品负责成交；借贷、保证金和策略产品支持资金使用；账户与链基础设施贯穿所有环节。

这里的“资产发现”指用户发现和理解可参与的资产，不等于发行资产，也不等于形成交易价格的“价格发现”。如果要讲价格发现，应分别落到发行定价、现货成交和 Perps 市场上。

本评审讨论**设计与叙事的对应程度**，不声称相关产品已上线、合作已落实或市场需求已验证。原图已保存为 [叙事思维导图](references/mantle-v3-narrative-mindmap.png)。

## 2. 原图中需要改动的地方

| 原图位置 | 判断 | 建议调整及理由 |
| :-- | :-- | :-- |
| 一级分支“资产发行” | 只覆盖供给，没有覆盖你在文字中提出的“资产发现” | 将“发行与引入”作为资产基础；发现主线补上资产信息、终端、分发和 Agent 交流入口 |
| Permissioned 下的 mStocks | 可以表达发行侧受准入条件约束，但范围不够明确 | 写为“美股相关资产发行与分发，按发行规则准入”；发行、转让、申赎和交易可能各有不同条件，不能只用一个标签概括 |
| Permissioned 下的 ETH/BTC | 分类不准确 | 改为“外部资产引入”：Mantle 接入 ETH/BTC 的链上表示，不负责它们原链上的发行；桥、托管或包装资产各自有信任条件 |
| Permissionless 下的 Meme Launchpad | 方向可保留，但需要限定 | 写为“开放式代币发行，按产品规则参与”；即使发币入口开放，所用 quote 资产的转让限制、授权、预算与风控规则仍然有效 |
| 交易质量下的 PropAMM、JIT Router | 方向正确，职责需要区分 | PropAMM/RFQ 提供报价，聚合器比较来源，JIT Router 在执行时重新检查路径和条件；Router 本身不会凭空创造流动性 |
| “转移交易用户” | 容易把迁移当作必然结果，也缩小了 Agent 的作用 | 改为“让人和 Agent 都能参与”。Agent 可以发现、发行、交易、做市和对冲；Bybit AI 等只作为候选入口 |
| Agent 下的 AA 地位提升 | 因果关系偏技术叙事 | 改为“受限授权、撤权、预算、代付与操作反馈”。这些是跨产品能力；AA 是实现选项，Native AA 是否必要仍需验证 |
| DeFi 场景下的 AMM DEX | 把现货交易的主体放得过深 | 与 PropAMM/RFQ 同列为现货执行来源，同时连接 Launchpad 的二级市场；是否毕业迁移取决于发行设计 |
| DeFi 场景下的 Lending | 相关，但不宜等同于一次交易 | 归为“交易后的资金使用与融资”：抵押资产借出资金，再按需求用于交易、保证金或其他用途；借贷能否带来真实需求要单独验证 |
| Perps 作为新增场景 | 正确，但应补上与现货的关系 | 展示 mStocks 持仓与合约对冲、库存管理和组合策略；Perps 成交量不自动证明 mStocks 现货被更多使用 |
| 缺少退出与持续使用 | 影响完整性 | 补上卖出、还款、撤权、平仓与提现。只说明用户怎样进入，无法说明是否形成可持续市场 |

不建议将 `Permissioned / Permissionless` 作为整个资产体系唯一的二分。更清楚的区分是“谁提供资产、用户怎样参与、哪些步骤需要准入”。准入规则是流程属性，不能代替产品分类。

## 3. 所有核心产品怎样贴合叙事

“直接”表示产品本身完成该环节；“间接”表示只有经其他产品协作才产生作用；“共用支撑”表示提供执行条件。这是功能关系，不是成熟度评分。

| 产品或能力 | 对资产发现的作用 | 对资产交易的作用 | 与 Mantle 生态的具体联系 | 仍需验证什么 |
| :-- | :-- | :-- | :-- | :-- |
| **mStocks** | 间接：提供值得被发现的资产供给 | 直接：作为现货标的；其他用途为候选 | 连接券商侧资产、链上现货与后续应用 | 发行与申赎规则、获取成本、可执行深度、持续使用 |
| **Agentic Meme Launchpad** | 直接：产生新资产与初次参与机会 | 直接：初始交易；后续市场需接续 | 尝试以 mStocks 计价，并连接二级交易 | 谁来发行和参与，毕业后是否继续交易，是否改善 mStocks 的实际使用 |
| **交易终端 / 资产信息入口** | 直接：展示、筛选、解释资产 | 直接：把发现转成报价、下单与仓位管理 | 可复用 Launchpad、聚合器、Perps 的服务；自建还是集成不预设 | 从看到资产到首笔成功交易的转化，跨产品体验是否顺畅 |
| **Agent 发现与交流社区** | 直接，但属于产品假设 | 间接：提供信息与参与意愿 | 类 Moltbook 的信息交流连接发行与交易入口 | 信息质量、操作者独立性、参与与复访，而非只数 Agent 数量 |
| **PropAMM / RFQ 与链下做市** | 间接：可执行报价帮助用户判断能否参与 | 直接：用库存与风险管理提供报价 | 给聚合器提供执行来源，也服务库存买卖与对冲准备 | 同规模订单的净报价、在线率、库存成本与极端行情表现 |
| **聚合器 + JIT Router** | 间接：整合可交易来源，降低寻找成本 | 直接：比较与选择路径，执行时检查状态 | 连接 PropAMM/RFQ 与公开 AMM；可研究将剩余价差收益返还用户 | 扣除费用后的实际到手量、成交成功率；返利取决于价差机会和原子执行条件 |
| **AMM DEX** | 间接：新交易对与价格信息可被终端发现 | 直接：现货买卖和二级交易 | 承接 Launchpad 后续交易，并成为聚合器的流动性来源 | 毕业/迁移是否顺畅，当前价格附近有多少深度，LP 是否愿意持续参与 |
| **Perps** | 间接：增加可参与的市场与策略 | 直接：方向交易、库存对冲、组合策略 | 与 mStocks 现货形成两条交易腿；抵押和 Vault 用途另行设计 | 合约与现货是否真正联动，是否有持续交易/对冲用户，是否能够安全退出 |
| **Lending** | 间接：增加资产用途 | 间接支撑：提供融资与资金周转 | 候选路径为资产抵押后借入稳定币，再按用户需求使用 | 抵押品可用性、价格与清算规则、真实借款用途、还款和坏账情况 |
| **Vault / 策略产品** | 间接：把策略变成可选择的产品 | 按用途支撑做市、风险承接或组合策略 | 可位于 Perps 或资金使用环节；不是所有 Vault 都做同一件事 | 策略、资金来源、费用和损失承担是否清楚；不能只用“收益”概括 |
| **账户 / AA / SDK / 状态服务** | 共用支撑：身份、授权、可编程接入 | 共用支撑：限权、代付、提交、回执与撤销 | 服务 Launchpad、现货、Perps 和按需接入的 Lending | 授权能否强制执行，费用是否可控，失败能否恢复；标准支持不等于完整体验 |

**与叙事最直接的关系**是 Launchpad 的发行参与、终端/社区的发现、现货执行能力，以及 Perps 的持续交易。mStocks 提供贯穿多产品的核心资产；Lending 与 Vault 的贴合度取决于具体资金用途；AA 与链能力属于共用支撑。

从当前材料看，最需要补证据的是三处：发现入口是否真的带来参与者；Launchpad 的 mStocks 计价是否改善资产使用，而不只是增加中间兑换；Perps 与 Lending 是否产生实际对冲或借款需求。报价与执行方案写得较细，也仍需用实际到手数量和持续服务能力验证。产品名称能放进图里，只能证明功能上有关联。

ETH/BTC、稳定币和 mETH/cmETH 应作为资产与资金类别标注，不与产品名称混在一列。mStocks 是这次分享的核心资产，但不能因此把 xStocks、bStocks 或其他发行人的资产混称为 mStocks，也不应把稳定币在支付、保证金和借贷中的作用省略。

## 4. 需要补清楚的四条业务路径

这些是需要验证的组合路径，不代表每个用户都必须依次经历所有产品。

1. **发现与参与**：用户或 Agent 从终端/信息渠道找到资产，了解规则、获取所需计价资产，再进入 Launchpad 或二级市场。检查发现到成交的转化，而不是只统计新发资产数。
2. **发行与二级交易**：Launchpad 初始交易结束后，按产品规则接入 AMM 等后续市场；新交易对和状态再回到发现入口。AMM 为聚合器提供报价来源，但不意味着任何代币毕业后都会获得专业做市商报价。
3. **持仓与对冲**：现货持有者或做市商用 Perps 调整价格敞口。两边需要匹配标的与数量，并管理成交先后、基差、资金费和清算风险；不是无风险套利。
4. **融资与退出**：符合规则的资产可用于抵押借款；借款是否进入交易或保证金由具体产品与用户决定。还款后解押，合约平仓后释放保证金，卖出后退出。不得假设同一份抵押品能在多个市场无限重复使用。

## 6. 怎样判断这种贴合度真的成立

| 叙事环节 | 应观察的结果 | 容易误判的替代指标 |
| :-- | :-- | :-- |
| 发现 | 看到资产后有多少独立参与者成功完成首笔操作，并再次参与 | 展示次数、新发币数量、Agent 账号总数 |
| 交易质量 | 同资产、同订单规模、同费用口径下的到手数量、成功率与等待时间 | 单看 TVL、某一次最优报价或理论延迟 |
| 发行后持续交易 | 发行后仍有成交和可用深度，用户能退出 | 只数发行成功或“毕业”数量 |
| 现货与 Perps 联动 | 有实际库存对冲、策略资金和可管理的风险 | 只用 Perps 总成交量推断 mStocks 现货需求 |
| 资金使用 | 真实借款用途、还款、保证金效率与可接受的损失 | 单看存款余额、抵押量或循环形成的 TVL |
| 生态共同使用 | 多个产品使用同一资产与可复用执行服务，减少不必要的兑换和迁移 | 仅统计接入协议数量 |

不先给每个产品打 1–5 分。已有资料足够判断功能关系，但没有一组可比的上线数据支持量化成熟度评分。
