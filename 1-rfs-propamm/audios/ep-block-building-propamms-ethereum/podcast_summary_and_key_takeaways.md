### 二、核心背景：从搜索者到以太坊顶尖区块构建者

在合并（The Merge）前的工作量证明（PoW）时代，矿池通过 Flashbots 开发的 MEV-Geth 直接从搜索者手中接收打包交易。合并转向权益证明（PoS）后，为了防止个人验证者（Home Validators）因为算力与算法劣势导致中心化，社区引入了 **提议者与构建者分离（PBS，Proposer-Builder Separation）** 架构。

Kubi Mensah 带领的 Gattaca 团队早期从事链上量化搜索（Searching），合并后凭借极高强度的底层系统工程优化，推出了 **Titan Builder**，迅速成长为以太坊出块份额最高的头部构建者之一。

本期访谈从**区块构建者的微观视角**出发，深刻剖析了区块构建这一“零和与博弈并存”的基础设施行业，并重点解答了：**区块构建者为何对专有做市 AMM（PropAMM / BopAMM）寄予厚望？构建者又是如何在区块顶部通过机制设计终结 LVR 损失的？**

### 三、核心技术与微观经济学原理解读

#### 1. 区块构建者的核心职责与数学本质
- **多维背包问题（Multidimensional Knapsack Problem）**：以太坊区块有 Gas 上限（通常 30M Gas），构建者的目标是**在 12 秒的时隙内，在毫秒级微观时间尺度下不断重排、合并成千上万笔交易与搜索者捆绑包（Bundles），使向验证者支付竞价后的净留存收益最大化**。
- **状态冲突（State Contention）与并行模拟**：多笔交易如果读写同一个合约存储槽（如 Uniswap 同一池子），不能简单并发执行。构建者必须拥有极致性能的 EVM 模拟引擎，能够毫秒级检测状态冲突并进行最佳排序。

#### 2. 区块构建行业的残酷经济学与补贴博弈
- **构建者利润极度微薄（甚至长期亏损补贴）**：
  - 为了赢得区块提议权，构建者必须在 MEV-Boost 拍卖的最后几百毫秒向提议验证者支付竞标出价（Bid）。
  - 在高度内卷的市场竞争下，顶级构建者经常将搜索者支付的优先费与 MEV 收益 **99% 甚至 100%+（自掏腰包补贴）** 转移给验证者，只为争夺更高的出块市场份额。
- **构建者的胜负手：私有订单流（Private Order Flow, POF）**：
  - 谁拥有独家订单流（用户未广播到公开交易内存池的交易），谁就拥有了竞争对手无法复制的确定性价值。
  - 这正是构建者极度渴望与 Telegram 交易机器人（Maestro、Banana Gun）、DEX 聚合器（1inch、CoW Swap）以及新型做市协议（Bebop）建立深度集成的原因。

#### 3. 构建者视角下的 PropAMM 与 BopAMM：降维打击 LVR
- **传统 CFMM 的结构性缺陷**：
  - 在 Uniswap 等传统池中，价格更新是由外部套利者（Arbitrageurs）驱动的。当币安等 CEX 价格暴涨时，以太坊上的套利者发起一笔交易将 Uniswap 低价现货买走，并在 CEX 上对冲。
  - 这笔价差收益被称为 **LVR（Loss Versus Rebalancing）**，其实质是外部套利者从被动流动性提供者（LP）身上吸血。套利者为了争夺抢跑权，向构建者支付高昂小费。
- **BopAMM 的解法：块首预言机重定价（Top-of-Block Repricing）**：
  - 头部构建者直接与 Bebop 及链上做市商协同。在区块的最开端（Top-of-Block，第 0 位置），构建者依据做市商最新低延迟报价流，插入一笔将 AMM 价格同步至市场最新公允价的交易。
  - **这一步彻底摧毁了针对过时报价（Stale Quotes）的原子套利空间**。套利者无利可图，做市商不再蒙受逆向选择损失，进而能够向普通终端用户报出与中心化交易所几乎无异的**极窄中间价价差（Sub-bps 级别）**。
  - 对于构建者而言，做市商将原本被外部黑客/套利者攫取的利润，转化为可预测的协议合作收益与独家优质订单流，实现了构建者与做市商的双赢。

#### 4. 延迟竞赛（Latency Wars）与物理拓扑
- **东京与欧洲的数据中心博弈**：构建者必须将接入网关与模拟节点部署在最靠近主流做市商与超级验证者的物理位置（如东京、法兰克福、弗吉尼亚等）。
- **区块竞拍截止窗口（The 1.5s Cutoff）**：在以太坊 12 秒的时隙中，构建者通常在第 10.5 秒到第 11.5 秒之间向中继器（Relay）提交最高竞价。延迟相差 50 毫秒，就可能导致错过最新的高价值交易包，从而满盘皆输。

#### 5. 抗审查性、包含列表（Inclusion Lists）与协议未来
- 针对当前少数大构建者可能因监管压力审查特定地址交易的担忧，Kubi 讨论了以太坊社区正在推进的 **包含列表（Inclusion Lists, EIP-7547 / FOCIL）** 机制。
- Kubi 认为，未来的构建者将逐渐从“单纯的排序拼装者”演进为“链上复杂金融产品的执行协同中枢”，而 PropAMM 是以太坊交易层走向机构化、资本高效化的里程碑之作。

### 四、核心术语速查表

| 术语 | 英文全称 | 核心含义 |
| :--- | :--- | :--- |
| **PBS** | Proposer-Builder Separation | 提议者与构建者分离，以太坊防范验证者中心化的核心分工架构。 |
| **MEV-Boost** | MEV-Boost | Flashbots 开发的带外出块中间件，验证者通过它向全网构建者拍卖区块提议权。 |
| **Knapsack Problem** | 背包优化问题 | 在 Gas 限制内组合最大化优先费收益的经典算法问题。 |
| **Private Order Flow**| 私有订单流 | 不经过公开 P2P 内存池，直接通过私密 RPC 提交给特定构建者的交易流。 |
| **Top-of-Block** | 块首执行位置 | 区块内排名最靠前的执行槽位，具有零状态污染和最高定价权。 |
| **LVR** | Loss Versus Rebalancing | 做市商/LP 相对主动外部对冲基准因被动逆向选择而损失的资金。 |
| **Inclusion List** | 包含列表 | 强制构建者必须打包特定合法交易以保障抗审查性的以太坊协议层提案。 |
