# 现货做市专属链优化（RFQ & Prop AMM Dedicated Chain Infra）

> **归属产品**：支柱 2 · 现货交易层（Fluxion RFQ & Prop AMM）  
> **核心命题**：为专业做市商私有库存报价、极速原子交割与杜绝 MEV 抢跑提供专属性的 Sequencer 排序与网络层优化。

---

## 1. 为什么 RFQ / Prop AMM 需要专属链优化？

传统公链（如以太坊主网或一般 L2）的通用排序规则对专业做市商（Market Maker）极不友好：
1. **公开交易池的 MEV 剥削**：做市商提交的报价订单在公共 Mempool 中被套利 Bot 窥探，交易极易遭遇三明治夹击（Sandwich Attacks），逼迫做市商扩大点差保护自身，恶化用户交易体验。
2. **行情剧烈跳空时的「撤单-吃单」恶性竞速**：标的资产（如美股财报发布时）价格瞬间剧烈变动，做市商需要撤销旧报价。而在通用 FIFO 或 gas 竞价规则下，taker 吃单往往先于撤单打包，导致做市商被套利扫货（Stale Quote Arbitrage）。
3. **确认延迟阻碍资本周转**：传统的区块级确认（2 秒或更长）导致做市商对冲头寸处于暴露窗口，限制了报价深度。

## 2. 专为 Fluxion 打造的链级优化矩阵

```
 ┌────────────────────────────────────────────────────────────────────────┐
 │                   RFQ / Prop AMM 专属链级优化                          │
 ├────────────────────────────────────────────────────────────────────────┤
 │ 1. 无公开 Mempool 承诺 (Private Mempool by Design)                     │
 │    - Taker 签名的 RFQ 交易直接通过加密 RPC 提交至 Mantle Sequencer     │
 │    - 在交易打包前不向全网 P2P 广播，在物理层彻底杜绝三明治夹击         │
 ├────────────────────────────────────────────────────────────────────────┤
 │ 2. 做市商撤单优先通道 (Cancel Priority FIFO)                           │
 │    - Sequencer 内置对标 Hyperliquid 的撤单优先语义                     │
 │    - 标记为 `CancelRFQ` 或更新 `minValidNonce` 的做市指令享受强制优先  │
 │      打包通道，确保撤单永远快于恶意吃单，保护 Bybit 与合作 MM 资本安全 │
 ├────────────────────────────────────────────────────────────────────────┤
 │ 3. Flashblocks 200–250ms 亚秒级预确认流                                │
 │    - Sequencer 在 2 秒出块周期内，每隔 200ms 持续向网络广播预确认状态  │
 │    - 做市商与用户在 200ms 内获知交易执行结果，立即启动 CEX 对应对冲    │
 └────────────────────────────────────────────────────────────────────────┘
```
